# zdef and zdefc: implementation notes

Status of the definition format implementation of
[`device-support.md`](device-support.md) (sections 6–9, 12–14): what is
built, how it is validated, what it costs, and where the implementation
fixed details the spec left open.

| Crate | Role | Targets |
|---|---|---|
| [`crates/zdef`](../crates/zdef) | data model, canonical CBOR, content hash, bytecode verifier and VM, matching, layer resolution, bank reader, COSE/Ed25519, manifest | `no_std` + `alloc`; host, thumbv7em, xtensa-esp32s3 |
| [`crates/zdefc`](../crates/zdefc) | strict YAML 1.2 / JSON / JSONC / JSON5 parser, JSON Schema validation, expression compiler and decompiler, CBOR → YAML/JSON/JSON5, bank/shard/manifest builder and signer, CLI | host (std) |
| [`crates/zdefc-wasm`](../crates/zdefc-wasm) | wasm-bindgen API of zdefc for the web UI (D15) | wasm32-unknown-unknown |
| [`schema/zdef-v1.schema.json`](../schema/zdef-v1.schema.json) | JSON Schema 2020-12 of the source form, generated by `zdefc schema` | — |
| [`tools/zdef-size`](../tools/zdef-size) | code-size probe of the hub entry points | xtensa-esp32s3, thumbv7em |

The `zdef` API (the contract with the hub entity engine) is described in
[`crates/zdef/README.md`](../crates/zdef/README.md).

## Validation level

Host-tested only; nothing here runs on the hub yet (no hardware gate is
claimed).

- **Golden tests**: every `definitions/examples/*.yaml` compiles; the CBOR is
  committed under `crates/zdefc/tests/golden/` and must not change silently.
  With `requires` disabled the output is **byte-identical to
  `tools/zdefc-proto` for 12 of 13 examples**; `philips-rwl022-dimmer`
  differs on purpose (constant order, below).
- **Round trip**: YAML → CBOR → YAML/JSON/JSON5 → CBOR is byte-identical for
  every example and the decompiled text is stable.
- **Format equivalence**: hand-written JSON5 and JSONC versions of two
  examples compile to the same bytes as the YAML; key order in the source
  does not change the output.
- **Schema**: the published schema equals the generator output and is
  checked with an independent JSON Schema 2020-12 implementation
  (`jsonschema` crate) against the examples and broken documents.
- **Expressions**: the spec 7.6 table reproduces byte for byte; 4 000 random
  well-typed programs (with `let`, `??`, ternaries, calls) are compiled,
  verified, decompiled and re-compiled to the same bytes, and evaluated on
  the VM against an independent reference interpreter (32 000 evaluations,
  including run-time errors).
- **Robustness**: 20 000 mutated golden CBOR files and 5 000 random inputs
  through the decoder, validator, bank parser and COSE parser; 200 000
  random byte programs through the verifier and the VM. No panics; verified
  programs never fail structurally (stack, jump, malformed).
- **Matching and resolution**: scoring table, Tuya packed names, trimming,
  case sensitivity, white labels, GP masks and SrcID ranges, tie-breaks,
  `requires` skipping, precedence user > self-description > catalog >
  generic, `self_description: under/ignore`, field-level patches,
  `present_if` over FlowerX model bits (5/7/5/8 entities for bits 0–3).
- **Banks**: build from the examples, signature and body-hash verification,
  index lookup for Zigbee names and a masked GP model ID, tamper tests
  (body, header, wrong key), manifest and shard verification, size limit.
- **WASM**: built in CI, wasm-bindgen package, Node smoke test against the
  golden CBOR.

## Sizes

### Code (hub entry points, `tools/zdef-size`)

Linked images with `--gc-sections`, `opt-level = "s"`, LTO, measured on
2026-11-20 (`.text` + `.rodata`, bytes). Each row links only that entry
point (with what it pulls in); "all" links everything a hub would use.

| Entry point | xtensa-esp32s3 | thumbv7em (proxy) |
|---|---:|---:|
| `zdef::load` (decode + validate + bytecode verifier + `requires`) | 97 959 | 81 216 |
| `Vm::eval` (interpreter, built-ins, float formatting) | 37 007 | 34 492 |
| `select_best` + `lookup_hashes` (matching) | 19 157 | 13 464 |
| `resolve` (layers, merge, `present_if`) | 54 135 | 49 388 |
| `Bank::parse/verify/load_strings/load` (incl. decoder, SHA-256, Ed25519, inflate) | 113 635 | 85 425 |
| **all of the above** | **200 371** | **156 470** |

Biggest contributors in "all" (xtensa): definition decoder 43 KB, core
formatting/sorting 30 KB, Ed25519 16 KB (`opt_size`), VM 12 KB, validation
messages 10 KB, inflate 7 KB, SHA-256 5 KB. This is above the spec 16.5
estimate (CBOR decoder ~15 KB, VM + verifier ~12 KB, Ed25519 ~15 KB);
see "Open points".

### RAM

| Item | 32-bit (xtensa) | 64-bit host |
|---|---:|---:|
| `size_of::<Definition>()` | 336 B | 584 B |
| `size_of::<Entity>()` | 472 B | 704 B |
| `size_of::<Vm>()` (512 B string arena) | 516 B | 520 B |
| `size_of::<Value>()` | 16 B | 24 B |
| VM value stack (16 slots, on the Rust stack) | ~384 B | ~512 B |

Live heap of one decoded definition (`cargo test -p zdef --test ram --
--nocapture`, 64-bit host; 32-bit is roughly 60 % of it): 2.2 KB
(`gp-zigbee-rs-switch`, 181 B CBOR) to 17.4 KB (`tuya-ts0601-trv-me167`,
1 054 B, 18 entities); average 6.7 KB, peak during load +5 %. The decoded
model is meant to be transient (spec 16.4: compiled into per-device tables,
then dropped); `Entity` dominates.

### WebAssembly

`cargo build -p zdefc-wasm --profile wasm --target wasm32-unknown-unknown`
plus `wasm-bindgen --remove-name-section`: **638 KB, 231 KB gzipped**
(without `wasm-opt`).

### Definitions

`zdefc measure definitions/examples` (spec appendix 20 is updated with
these numbers): 156–1 054 B standalone CBOR; 13 catalog forms in one block
deflate to 2 971 B (228 B per definition). A bank of the 12 non-fragment
examples is 3 898 B: 17 shared strings, 54 index keys, 2 blocks.

## Decisions the implementation fixed (spec updated)

1. **Constant-pool order is canonical.** The prototype assigned constants in
   YAML key order, so reordering keys in the source changed the CBOR and its
   hash. zdefc compiles expressions in a fixed traversal order (spec 7.5);
   this is the only change of bytes against the prototype in the examples
   (`philips-rwl022-dimmer`: the trigger's `attrs` key 6 is now visited
   before `event` key 15).
2. **`requires` is computed** (the prototype left it out), so every
   definition that uses expressions, Tuya, GP or a codec is 3–5 B larger
   than in the old appendix.
3. **Decimal fractions use the exact shortest decimal** of the f64; the
   prototype's `1e-12` tolerance could encode `0.30000000000000004` as
   `0.3`.
4. **Floats in the constant pool stay floats** (`x * 2.0` keeps float
   semantics); the prototype turned integral pool floats into integers.
5. **Packed Tuya names** apply to every manufacturer matcher (exact and
   `any`); the white-label index list includes exact names. The prototype
   packed only `any` lists.
6. **Key tables v1** are complete and live in `crates/zdef/src/keys.rs`;
   the optional-extension range 64–127 applies to every map, so the shared
   sub-map table continues at 128.
7. **Index keys** are concrete CBOR values hashed with SipHash-2-4; the
   fingerprint-only key is `(mfr code or null, profile, device ID)` of the
   lowest endpoint with both, because a hash of the clause's whole endpoint
   structure cannot be computed from a device's superset of clusters.
8. **Bank layout** (header fields, detached COSE payload, string-table
   section, slot prefixes, shard records, manifest keys) is fixed in spec
   9.1/9.3.
9. **Strict YAML** rejects every plain scalar that YAML 1.1 and 1.2 read
   differently, not only `on/off/yes/no` (spec 6.1).
10. **Scoring** of clause shapes the table did not list (spec 3.3).

## Open points

- **Code size** is about 200 KB on the S3 for everything, versus ~42 KB
  estimated for decoder + VM + Ed25519. Candidates: a table-driven decoder,
  the ROM `tinfl` through the existing `bank::Inflate` trait, mbedTLS
  SHA-256 behind a trait, static validation messages instead of `format!`.
- **`Entity` is 472 B on 32-bit**; boxing rarely used fields would cut the
  transient RAM of large definitions roughly in half, at the cost of an API
  change for the engine.
- Named codecs (6.6) are parsed, encoded and feature-gated, but their
  byte-level implementations belong to the hub runtime.
- `cargo fuzz` targets are not set up; the fuzz-style tests are
  deterministic and run in CI.
